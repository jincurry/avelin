# 路线图

本页说明方向，不承诺固定时间或尚未验证的兼容能力。

## 当前：Rust 原生引擎

已具备配置初始化、检查和构包，品牌化原生 UI，当前用户安装、完整包升级、受控卸载、静默入口、诊断、显式恢复与同版本修复。构包和部署统一使用 x64 Rust worker，旧后端和引擎选择入口已移除。验收范围与复现命令见[开发指南](development.md#rust-引擎真实进程验收)。

支持边界见[兼容约定](compatibility.md)。源码公开不表示全部发布验收已完成。

## Rust 维护操作

- 恢复：原进程退出后检查 schema 2 持久事务，未提交变更回退，已提交结果核验确认，验证结束后解除遗留标记和锁。
- 修复：使用相同构建的原始 Setup 补回缺失资源；修改项默认保留，显式恢复原版前先备份。
- 组件：紧凑清单选装、完整离线包、升级继承选择，以及同版本原包增删；修复与恢复不改变已冻结选集。配置和操作见[可选组件](optional-components.md)，已发布 `v0.1.0-preview.1` 尚不包含此源码新增能力。
- 入口：原 Setup 提供维护确认页和静默参数，CLI `recover` 默认只读检查、`--apply` 显式执行；部署变更仍由认证 Rust worker 负责。

这些操作保持当前用户、离线完整包及用户数据保护边界。旧恢复记录不足时拒绝，修复不接管缺失 receipt 的任意目录。命令和行为见[恢复与修复](maintenance.md)。

## Rust 引擎本阶段验收

当前验收覆盖以下生命周期，结果对应报告记录的组件与输入：

1. 未压缩载荷读取、部署、系统入口、取消和归属卸载。
2. 完整包升级、暂存/备份、完整提交、有限进程内回滚与用户内容保护。
3. 部分写入、提交前后失败、恢复失败、异常退出和只读诊断。
4. 显式恢复、恢复再次中断与重入、资源冲突保留、同版本修复及覆盖前备份。
5. 组件默认/显式选择、只管理选中文件、同版本增删、升级继承、旧记录迁移、用户文件保护与中断恢复。

异常退出与显式恢复覆盖脚本列出的事务暂停点，不代表任意指令中断或机器重启恢复。旧非 Rust 安装不再自动接管。

当前原生载荷不压缩，保留现有包大小限制；压缩与性能优化单独评估，不预先承诺收益。性能、签名和独立环境测试不在本轮范围。
